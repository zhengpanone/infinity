# ADR-0004: JSON Formatter

**状态**: Accepted  
**日期**: 2026-06-15  
**作者**: @maintainer

---

## 背景

需要支持结构化日志输出。

目标：
- 便于日志系统解析
- 生产环境标配
- 保留所有字段信息

---

## 决策

通过 **Feature Gate** 提供 JSON 格式支持。

### Feature 定义

```toml
[features]
json = ["tracing-subscriber/json"]
```

### 使用方式

```rust
Logger::builder()
    .json(true)
    .init()?;
```

---

## 理由

### 为什么需要 JSON？

1. **机器可读**
   - ELK Stack
   - Grafana Loki
   - 日志分析系统

2. **保留结构**
   ```rust
   tracing::info!(user_id = 123, method = "POST", "Request");
   ```
   
   输出：
   ```json
   {
     "timestamp": "2026-07-03T12:00:00Z",
     "level": "INFO",
     "fields": {
       "user_id": 123,
       "method": "POST",
       "message": "Request"
     }
   }
   ```

3. **标准化**
   - 统一格式
   - 便于聚合

### 为什么 Feature Gate？

1. **可选依赖** - 不用 JSON 的用户无需编译相关代码
2. **减小体积** - 默认不包含 JSON 序列化
3. **灵活性** - 按需启用

---

## JSON 格式

### 紧凑模式（默认）

```json
{"timestamp":"2026-07-03T12:00:00.123Z","level":"INFO","target":"app","message":"Login"}
```

### 美化模式

```rust
Logger::builder()
    .json(true)
    .json_pretty(true)  // ← 美化
    .init()?;
```

```json
{
  "timestamp": "2026-07-03T12:00:00.123Z",
  "level": "INFO",
  "target": "app",
  "message": "Login"
}
```

---

## 配置选项

```rust
pub struct JsonConfig {
    pub enabled: bool,
    pub pretty: bool,
    pub flatten: bool,
}
```

### flatten

```rust
// flatten = true（默认）
{
  "timestamp": "...",
  "user_id": 123,
  "message": "Login"
}

// flatten = false
{
  "timestamp": "...",
  "fields": {
    "user_id": 123,
    "message": "Login"
  }
}
```

## 实现

### Layer 实现

```rust
// src/layer/json.rs

pub fn layer(config: &LoggerConfig) -> Option<impl Layer<Registry>> {
    if !config.json.enabled {
        return None;
    }
    
    let layer = fmt::layer()
        .json()
        .with_current_span(true)
        .with_span_list(false);
    
    Some(layer)
}
```

### 依赖

使用 `tracing-subscriber` 内置 JSON 支持：

```toml
tracing-subscriber = { version = "0.3", features = ["json"] }
```

## 与其他格式共存

### 同时启用

```rust
Logger::builder()
    .console(true)  // 控制台：文本
    .file(true)     // 文件：JSON
    .json(true)
    .init()?;
```

### 分离输出

- Console: 彩色文本（开发）
- File: JSON（生产）

---

## 性能考虑

### JSON 序列化开销

- **额外开销**: 约 10-20%
- **可接受**: 生产环境换取可分析性

### 优化

1. 紧凑模式（无空格）
2. 复用 Buffer
3. 异步写入

---

## 备选方案

### 方案 1: 自定义 JSON 格式

**缺点**:
- 重复造轮子
- 维护成本高
- 性能未必更好

### 方案 2: 总是启用

**缺点**:
- 增加默认依赖
- 用户无法选择

### 方案 3: 独立 Crate

```toml
infinity-logger-json = "0.1"
```

**缺点**:
- 分散维护
- 用户集成复杂
